# Lookup hosting: free / near-free shortlist

**Checked 2026-11-08.** Public first-party documentation only; no accounts accessed or deployment attempted. USD list prices, before applicable taxes; region, billing agreement, and future changes matter. “Free” below means a recurring allowance, not a guarantee of a zero bill.

## What we are hosting

Project facts supplied for this comparison: Python 3.13+, MCP SDK 1.30, Starlette/Uvicorn; stateless Streamable HTTP with JSON responses and two note-free terminology tools. Two immutable public CDC ICD-10-CM SQLite catalogs total **334,323,712 bytes (~319 MiB on disk)**. Bundle/build those catalogs into the application image and open read-only: no managed SQL database, persistent volume, or GPU is required for core exact/codephrase lookup.

Optional OpenMedNER/PII stays local (measured up to ~722 MiB RSS). These are **public/synthetic-input prototypes, not clinical/PHI-certified services**. Shared bearer authentication, Host/Origin validation, and a 64 KiB body limit remain necessary; a cloud account does not provide application security automatically.

## Account and hidden-cost checks

- **Render:** free docs explicitly describe operation without a payment method; without one, bandwidth exhaustion suspends services and build exhaustion disables new builds. With one, overages can charge. Account-specific verification was not tested.
- **Railway:** [pricing](https://railway.com/pricing) says no card required for Free; paid subscriptions accept cards. Trial verification uses GitHub/account signals and unverified trials restrict outbound networking. Volumes cost $0.15/GB-month, but are unnecessary here.
- **Google:** ongoing use needs an eligible active billing account. [Trial](https://docs.cloud.google.com/free/docs/free-cloud-features) is separately $300/90 days, requires payment-method verification, and needs manual paid upgrade to continue afterward. Cloud Build, logging, registry and network billing are separate. [Artifact Registry](https://cloud.google.com/artifact-registry/pricing) includes only **0.5 GiB-month/account**; total image/dependency size and retained revisions matter. Cloud Run includes just **1 GiB North American internet transfer/month**.
- **Azure:** [signup](https://azure.microsoft.com/en-us/pricing/purchase-options/azure-account) documents phone, non-prepaid card and Microsoft/GitHub account; continuing beyond the separate $200/30-day trial requires pay-as-you-go. Public registries are supported: paid [ACR](https://azure.microsoft.com/en-us/pricing/details/container-registry/) is not mandatory. [Log Analytics](https://azure.microsoft.com/en-us/pricing/details/monitor/), egress, builds, registry, optional storage and identity-dependent integrations need separate cost review. Avoid Dedicated profiles/private-endpoint features that introduce management charges.
- **Fly:** card needed beyond trial; current [canonical trial page](https://docs.fly.io/about/free-trial) offers **$1 once / 7 days**, with five-minute automatic trial Machine stops. Other first-party pages still describe two runtime hours: trial details are inconsistent, but neither is ongoing free hosting. Builders/registry currently free; shared IPv4/IPv6 free; dedicated IPv4 $2/month; North America/Europe egress $0.02/GB. Avoid unintentionally paying for multiple Machines.

Cloud quotas are **not spending caps**. [Google alerts-only budgets](https://docs.cloud.google.com/billing/docs/how-to/budgets) and [Azure budgets](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/quick-create-budget-template) do not themselves stop consumption.

## Recommendation and remaining verification

**Convenient free demonstration:** Render Free, conditional on Linux memory testing and tolerating minute-long wakes. **Low-cost always-on:** Fly, budget roughly $6.70 compute for one 1 GB iad Machine, plus extras; 512 MB is cheaper only if measured sufficient. Render’s $7/512 MB paid compute is another predictable managed baseline. Railway Hobby is convenient but usage-metered, not a fixed $5 ceiling.

**For our build:** prefer **Azure Container Apps Consumption** if the later Azure direction matters; otherwise Cloud Run request-based is a strong sparse-traffic alternative. Both can stay within recurring compute grants but require billing vigilance.

Ephemeral filesystems are fine for image-bundled immutable catalogs; they are not fine for irreplaceable runtime writes. **319 MiB disk is not 319 MiB RSS.** Cloud Run specifically charges memory consumed by filesystem writes; do not extrapolate that rule to every host. Linux RSS/caches, image size, startup latency and end-to-end MCP auth/proxy/reconnection behavior remain unverified on all five. Validate those before choosing memory or promising $0. No defaults, source, accounts, or deployments were changed by this research.
